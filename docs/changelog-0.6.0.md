# 0.7.0 起：语义检索（本地嵌入）

## 0.7.0：本地语义检索

**能力**：在文件名与正文 FTS 之外，增加「语义召回」——问法不必和原文用词一致，也能找得到。

**实现**

| 部分 | 做法 |
|---|---|
| 切块 | 正文按约 400 字、重叠 80 字切块，优先在段落/句号处断开，单文档上限 40 块 |
| 嵌入 | 本地 ONNX（fastembed + ge-small-zh-v1.5），模型按需下载到 %APPDATA%\com.tracefind.desktop\models，不打包进安装包 |
| 存储 | chunk（文本块）+ chunk_vec（f32 向量 BLOB），随文件删除一起清理 |
| 查询 | L2 归一化后点积，向量表常驻内存并随块数失效重建 |
| 融合 | 文件名 / 正文 / 语义三路 RRF（k=60，权重 1.0 / 0.6 / 0.8），语义最多贡献 8 条 |
| 开关 | 设置 → AI 与模型，默认关闭；关闭时不下载、不加载、不占内存 |

**实测**

`
模型下载         90.9 MB（解压后），首次启用下载，之后启动 128 ms 加载
文本块/向量      15,410 / 15,370（14,597 个文件里可抽取正文的部分）
查询延迟         嵌入 2 ms + 万级向量点积，总 5 ms；冷启动首个查询约 70–100 ms
exe 体积         14.3 MB → 43.7 MB（ONNX Runtime 静态链接，无额外 DLL）
`

**已知取舍**

1. 阈值 MIN_SCORE = 0.50：bge-small-zh 对无关文本的相似度常到 0.4 附近，阈值低会灌进来噪声。
2. 语义只做「补召回」，排序仍以文件名命中为先（RRF 权重已体现）。
3. 云端嵌入接口尚未接入；本期所有向量都在本机计算，不出网。

# 0.6.1 / 0.6.0 修复清单

## 0.6.1：隐藏后回不来（快捷键被占用）

**现象**：从搜索窗打开文件后，窗口按设计隐藏；但用户按 Alt + Space 没反应，只剩托盘图标，看起来像“软件退出了”。
根因不是崩溃，而是 Alt + Space 被本机其他程序占用，注册一直失败，隐藏后没有任何唤起入口。

修法：

1. egister_with_fallback()：配置的组合失败时依次尝试
   Ctrl+Alt+Space → Ctrl+Shift+Space → Alt+Shift+Space → Ctrl+Alt+Q → Ctrl+Shift+F12
2. RuntimeInfo 暴露 hotkey（实际生效）、hotkeyConfigured（配置值）、hotkeyFallback
3. 状态栏常驻「快捷键已降级」胶囊（可点进设置），设置页给出说明，托盘菜单显示当前组合
4. 新增事件 ura:hotkey-fallback
5. 重新唤起时**保留上次搜索词**：关掉文件后按热键回来，还是原来的查询

实测：启动日志 快捷键 Alt+Space 不可用…已降级为 Ctrl+Alt+Space，
模拟真实按键后 全局快捷键触发（真实按键）→ 窗口已显示 间隔 **12 ms**。

# 0.6.0 修复清单

这一版不改功能，只修"结果可能错、交互可能失手"的问题。每条都对应一次提交，可按 commit 回溯。

## 一、索引正确性

| 问题 | 修法 | 证据 |
|---|---|---|
| `D:\Work` 会命中 `D:\Workbench` | `scope_patterns()` 生成 `path = root OR path LIKE 'root\\%'`，search/recent/子序列/正文四处统一 | 单测 `scope_respects_directory_boundary` |
| 移除目录后仍返回其文件 | `remove_root` 保存后立即 `purge_paths()`；`patch_settings` 对被移出的根、新增的排除项同样清理 | 隔离 E2E「删除后从索引消失」 |
| 新增目录里的旧文件搜不到 | `spawn_root_scan()` 只补扫新目录，沿用当前代数、不做 prune | 手动验证（加入即见） |
| 删除文件不清理正文 | `delete_paths` 同事务删 `files`/`doc_text`/`doc_fts`/`doc_body` | 隔离 E2E「删除后正文不再命中」 |
| 扫描期间的变更丢失 | 事件不再丢弃，攒在 pending，扫描结束后重放；积压 >5000 转为全量补扫 | 隔离 E2E「新建文件 5s 内可搜到」 |
| 监听报错后索引长期缺数据 | `notify` 出错时自动安排一次全量扫描 | 代码路径 + 日志 |

## 二、正文版本

| 问题 | 修法 |
|---|---|
| 同秒覆盖、mtime 不变导致不重抽 | `doc_text` 增加 `size` 列，与 mtime 一起比较 |
| 覆盖后仍命中旧正文 | 监听 `Modify` 事件显式 `invalidate_docs()`：删状态与 FTS 行，下一轮重抽 |
| 提取失败仍能搜到旧正文 | 失败/崩溃时先失效再标记 failed |
| 片段里中英文空格被吞 | 新增 `doc_body` 表存原文，片段改成从原文 `substr/instr` 截取，删除有损的 `desegment` |
| 正文入库后要重新输入才看到 | Launcher 监听 `index:content`（800ms 节流）自动刷新 |
| 正文结果被文件名挤掉 | `search_files` 给正文预留 `limit/3`（2–10）个槽位 |
| 开关文案与行为不一致 | 文案改为"关闭后停止抽取，搜索结果只含文件名与路径" |

## 三、交互与稳定性

| 问题 | 修法 |
|---|---|
| 改绑快捷键时旧键先被释放 | 先注册新组合，成功后再 unregister 旧的；相同组合直接返回 |
| 标题栏按钮键盘按不动 | 事件源在 `button` 上时不劫持 Enter/Space |
| 退场动画中唤起，UI 相位停在 hiding | `launcher:focus` 时把 `hiding` 收敛为 `visible` |
| 后台刷新后按 Enter 打开错文件 | 按 path 记录选中项，刷新后恢复 |
| Office 解压无上限（zip bomb） | 单条目 64 MB、单次 128 MB、PPTX 500 页 |
| 扫描根位于 AppData/Program Files 时监听全失效 | `ignored_path` 只检查扫描根之下的路径组件 |

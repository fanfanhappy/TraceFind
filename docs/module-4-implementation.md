# TraceFind · 模块四实现（正文索引）

前三阶段解决了"外壳、索引、实时更新"，这一阶段补上**正文检索**：
把文档里的文字抽出来写进 FTS5，于是"托盘"这种只出现在正文里的词也能被搜到，
并带回命中片段。

- 版本：0.4.0（M4）
- 新增依赖：`zip`、`quick-xml`、`encoding_rs`、`pdf-extract`
- 入口：`src-tauri/src/extract.rs`（抽取）、`docindex.rs`（队列）、`index.rs`（FTS）

## 一、覆盖的格式

| 类型 | 做法 |
|---|---|
| TXT / Markdown / 代码 / CSV / JSON / 日志 | 直接读，UTF-8 失败时按 GBK 解码（中文环境常见） |
| DOCX | 解压 `word/document.xml`，按 `w:t` 取文本、`w:p` 断段 |
| PPTX | 逐页读 `ppt/slides/slideN.xml`，按 `a:t` 取文本 |
| XLSX | 读 `xl/sharedStrings.xml`（共享字符串里是主要文本） |
| PDF | `pdf-extract` 抽可选中文本 |
| HTML | 剥标签 |

扫描件（图片型 PDF）取不到文字，会记为 `failed` 并保留原因；OCR 留给后续模块。

## 二、中文分词：为什么要把字拆开

FTS5 的 `unicode61` 按空白与标点切词，中文没有空格，整句会变成一个 token，
"预算"这种词永远搜不到。所以入库前把每个中日韩字符拆成独立 token：

```
原文：本季度预算报告已提交
入库：本 季 度 预 算 报 告 已 提 交
查询：预 算  →  MATCH '"预 算"'（短语，要求相邻）
```

查询侧做同样处理并包成短语，得到精确的连续子串匹配；英文仍按正常单词匹配。
展示时 `desegment()` 把补的空格去掉（只去掉空格两侧含中日韩字符/标点的），
所以片段读起来仍是"…到托盘而非退出；明确的托盘"退出…"。

## 三、队列与调度

```
pending_docs()：files 左连 doc_text，取「没有记录」或「mtime 变了」的文件
   ↓ 每批 6 个
抽取 → put_body(FTS) → mark_doc(done/failed, mtime, chars)
   ↓ 每篇之间 sleep 25ms
emit index:content { done, failed, chars, pending, enabled }
```

- 全量扫描期间让路（`scan_running` 时睡 400ms 再试）
- 设置里可整体关闭（`contentIndex`），关掉后不再更新但已提取的仍可搜
- 单文件上限：16 MB 输入、20 万字符入库（防止巨型日志把索引撑爆）
- **第三方解析器崩溃隔离**：`pdf-extract` 遇到不支持的编码（如 `UniGB-UCS2-H`）
  会直接 panic，不隔离会打死整个 worker 线程 → 用 `catch_unwind` 包住，记为 failed

## 四、搜索合并策略

1. 文件名/路径/拼音命中（模块二）先排，结果稳定
2. 正文命中补在尾部；同一个文件若两边都命中，只补一条片段
3. 单字符词（`a`、`的`）跳过正文检索——在 6000 万字里几乎命中所有文档，
   FTS5 要为整库算 bm25，实测 812 ms；加上这条规则后降到 3.6 ms

## 五、实测（本机 14,596 个文件）

| 指标 | 结果 |
|---|---|
| 可抽取文件 | 503（其余是图片/压缩包/可执行文件） |
| 成功提取 | **490 篇**，6,145 万字 |
| 失败 | 13（PDF 用了不受支持的 CID 编码） |
| 全量提取耗时 | **22 s**（约 22 篇/秒，带 25ms 限速） |
| 搜索 P50 / P95（含正文） | **10.5 ms / 28 ms**（不含正文时 9.2/14.9） |
| 索引库体积 | 约 133 MB（含 FTS 索引） |

抽出来的内容确实在起作用：搜「托盘」「窗口规格」「玻璃」「快捷键注册」都能命中
`示例设计说明书.docx` 并给出上下文片段。

## 七、已知边界

1. **扫描件 / 图片型 PDF**：没有 OCR，取不到文字。
2. **部分中文 PDF**：`pdf-extract` 不支持某些 CID 编码（`UniGB-UCS2-H` 等），
   会失败但不会影响其它文件。
3. **XLSX 只取共享字符串**：公式结果与内联字符串覆盖不全。
4. **20 万字符截断**：超长文档只索引前 20 万字。
5. **不建外部内容表**：FTS 里存的是分段后的文本，原文不另存；需要原文片段时从文件重读（留给预览模块）。
